# Experiment log

A dated record of every experiment, including the ones that failed. Write
the entry **before** looking at results (hypothesis and setup), then fill
in the result. Never delete or rewrite an old entry; add a correction below
it instead. This log is the source for the README's "what I tried / what
didn't work" section.

## Entry template

```
## E### — <short title> (YYYY-MM-DD)
**Question:** what we want to know.
**Hypothesis:** what we expect and why, written before running.
**Setup:** data version, split, model + version, parameters, command.
**Result:** numbers with confidence intervals; link to results/<file>.
**Conclusion:** what we now believe. Surprises.
**Next:** what this changes.
```

## E000 — Project decisions (2026-11-20)

**Question:** how should the evaluation be designed so its results are trustworthy?

**Decisions:**
- Ground truth is human labels on a 0–3 scale; a pair counts as a match at
  2 or higher. Gemini is one of the systems under test, so it cannot also
  be the judge.
- Dataset target: ~30 synthetic CV personas × ~15 real listings ≈ 450 pairs,
  with deliberate hard negatives (similar-looking but wrong roles).
- CVs are written from a persona spec rather than generated by Gemini, so
  the text is not stylistically "familiar" to the model being evaluated.
- Splits are by CV to avoid leakage.
- Label reliability: one labeller; 50 pairs re-labelled by the same person
  one week later, reported as intra-rater weighted Cohen's kappa. This
  measures consistency, not agreement between different people; that
  limitation is reported.
- Location, remote policy, salary and work authorization are excluded from
  labels (see labelling guide). The heuristic is run with neutral
  logistics filters so it is not penalized for signals humans ignored.

## E001 — Dataset design additions (2026-11-20)

**Decisions:**
- **Synthetic CV style is a limitation.** All 30 CVs are written by one
  model (Claude), so their style is likely more uniform than real CVs:
  cleaner structure, fewer typos, consistent tone. Mitigation: formats are
  varied on purpose (bullets, prose, mixed; short and long; with and
  without a skills section). Residual risk: systems that rely on surface
  wording may score better here than on real CVs. Reported in the README.
- **Language subgroup.** Each pair is tagged `same` or `cross` language.
  Metrics are reported overall and for the cross-language subgroup, which
  mostly means Turkish CVs against English listings.
- **Listing text stays out of git.** Only IDs, URLs and labels are
  committed, because provider redistribution terms are unconfirmed.
- **Calibration set.** Ten pairs labelled first to test the guide. They are
  excluded from the final dataset.
